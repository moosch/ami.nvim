1. INTRODUCTION                                           *ami-introduction*

ami is a Neovim plugin pairing you with a local LLM (via LM Studio) that
*advises, never acts*. It discusses problems, surfaces trade-offs, offers
inline completions, and occasionally a proactive suggestion — but it never
edits your files. You stay in control.

It is a pure-Lua Neovim plugin. There is no daemon: ami talks to LM Studio
directly over the OpenAI-compatible API (via curl). The core is a small runtime;
every feature is an extension.

==============================================================================
2. REQUIREMENTS                                           *ami-requirements*

  - Neovim >= 0.10 (uses |vim.system()|, |vim.uv|, |vim.fs.root()|)
  - curl on $PATH
  - LM Studio (or any OpenAI-compatible server) with a model loaded
  - Linux and macOS. Windows is untested but no longer excluded.

==============================================================================
3. INSTALLATION                                           *ami-installation*

Pure Lua — no build step. Install core plus the feature extensions you want. >
    {
      "moosch/ami.nvim",
      dependencies = {
        "moosch/ami-chat.nvim",
        "moosch/ami-history.nvim",
        "moosch/ami-inline.nvim",
      },
      config = function()
        require("ami").setup({
          extensions = {
            require("ami-chat"), require("ami-history"), require("ami-inline"),
          },
        })
      end,
    }
<
==============================================================================
4. SETUP                                                         *ami-setup*

                                                              *ami.setup()*
require("ami").setup({opts})

Call once. Registers commands, the model registry, and any extensions. See
|ami-configuration| for {opts}.

==============================================================================
5. COMMANDS                                                   *ami-commands*

Core provides the model/extension commands below. Feature commands come from
extensions: ami-chat.nvim adds :AmiChat, :AmiAsk, :AmiNewSession;
ami-history.nvim adds :AmiTree; ami-inline.nvim adds :AmiComplete,
:AmiInlineAuto; ami-proactive.nvim adds :AmiProactive, :AmiNudge. See
|ami-extensions|.

                                                                 *:AmiModel*
:AmiModel [slot]
                      Pick a model for a registered slot (live list from the
                      slot's provider). No argument prompts for which slot. Slots:
                      default, chat, and any an extension registers (e.g. fim).

                                                                *:AmiModels*
:AmiModels        Show each model slot's current model.

                                                            *:AmiExtensions*
:AmiExtensions    List the loaded extensions. Extensions add their own commands
                  (e.g. ami-inline.nvim adds :AmiComplete / :AmiInlineAuto;
                  ami-proactive.nvim adds :AmiProactive / :AmiNudge). See
                  |ami-extensions|.

                                                                *:AmiHealth*
:AmiHealth        Run :checkhealth ami (curl + provider reachability).

                                                                   *:AmiLog*
:AmiLog           Open the log viewer. *:AmiDebug* toggles verbose logs.

==============================================================================
6. CONFIGURATION                                         *ami-configuration*

Defaults (pass overrides to |ami.setup()|): >
    require("ami").setup({
      model = {                     -- default model slot (every slot falls back here)
        endpoint = "http://localhost:1234/v1",
        model = "qwen3-coder",      -- pick per slot live with :AmiModel
      },
      context = {
        lsp_deps = true, dep_max_files = 5,
        dep_timeout_ms = 1500, dep_max_positions = 30,
        token_budget = 8000,        -- max tokens of assembled context per turn
      },
      extensions = {            -- feature extensions (their own repos)
        require("ami-chat"), require("ami-history"), require("ami-inline"),
      },
      disable_extensions = {},  -- names of extensions to skip
    })
<
Chat lives in ami-chat.nvim, history in ami-history.nvim, inline in
ami-inline.nvim; install them and add them to `extensions`. An extension's own
options live under its name (e.g. `chat = { ui = {...} }`, `inline = { ... }`).
See |ami-extensions|.
==============================================================================
7. EXTENSIONS                                             *ami-extensions*

ami core is a runtime; every feature is an extension — a self-contained Lua spec
that hooks the lifecycle, registers commands / a model slot / a capability, all
through a stable API instead of core internals. Register specs, or module names
to require(), in |ami.setup()|: >
    require("ami").setup({
      extensions = {
        require("ami-chat"), require("ami-inline"),
        "my-org.ami-notes",               -- or a module name to require()
      },
      -- disable_extensions = { "inline" },
    })
<
ami ships no active extensions itself. First-party ones (each its own repo):
ami-chat.nvim (chat panel; provides the "chat" capability), ami-history.nvim
(branching history tree; provides the "history" capability), ami-inline.nvim
(inline/FIM completion), ami-proactive.nvim (proactive suggestions),
ami-chat-split.nvim (a split-window "chat_ui" provider). `:AmiExtensions` lists
what is loaded. Lifecycle events: setup, context_assembled, chat_session,
chat_turn_pre, chat_turn_post, buf_write.

Full API, event reference, model registry, the chat/chat_ui/history contracts, and
a guide to writing/publishing your own are in docs/extensions.md in the repository.

==============================================================================
8. HOW IT WORKS                                           *ami-architecture*

  Neovim (Lua)  --curl (HTTP + SSE)-->  LM Studio

ami talks to LM Studio directly — no daemon, no separate process, no build step.
The chat extension assembles each request (system prompt + context + prior turns
from the history provider + your message) and streams the reply from the model.

Conversation history is the ami-history.nvim extension (a branching tree persisted
under stdpath("data")/ami/<project>/, out of your repositories).

==============================================================================
9. HEALTH                                                       *ami-health*

Run `:checkhealth ami` to verify Neovim version, curl, and LM Studio (each model
slot's provider endpoint) reachability.
