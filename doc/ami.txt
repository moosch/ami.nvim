1. INTRODUCTION                                           *ami-introduction*

ami is a Neovim plugin pairing you with a local LLM (via LM Studio) that
*advises, never acts*. It discusses problems, surfaces trade-offs, offers
inline completions, and occasionally a proactive suggestion — but it never
edits your files. You stay in control.

It is a Lua plugin plus a small Go daemon (`amid`). The daemon holds the
intelligence (context assembly, history, LLM proxying); Neovim is a thin client.

==============================================================================
2. REQUIREMENTS                                           *ami-requirements*

  - Neovim >= 0.10 (uses |vim.system()|, |vim.uv|, |vim.fs.root()|)
  - Go (to build the daemon; auto-built on first run if present)
  - curl on $PATH
  - LM Studio (or any OpenAI-compatible server) with a model loaded
  - Linux (developed on macOS too). Windows is not supported.

==============================================================================
3. INSTALLATION                                           *ami-installation*

lazy.nvim: >
    {
      "moosch/ami.nvim",
      build = "make build",       -- compiles the Go daemon
      config = function()
        require("ami").setup({})
      end,
    }
<
The `build` step compiles `amid`. If omitted, the plugin auto-builds it on
first run when `go` is available.

==============================================================================
4. SETUP                                                         *ami-setup*

                                                              *ami.setup()*
require("ami").setup({opts})

Call once. Registers commands, the model registry, any extensions, and starts
the managed daemon (unless `daemon.auto_start = false`). See
|ami-configuration| for {opts}.

==============================================================================
5. COMMANDS                                                   *ami-commands*

                                                                  *:AmiChat*
:AmiChat          Toggle the chat panel (floating transcript + prompt).
                      In the prompt: <CR> (normal mode) sends, <C-n> new
                      session, q / <Esc> hides it (draft preserved).

                                                                   *:AmiAsk*
:AmiAsk {text}    One-shot question. In visual mode also sends the
                      selection (and its LSP dependencies) as context.

                                                            *:AmiNewSession*
:AmiNewSession [name]
                      Start a fresh conversation.

                                                                  *:AmiTree*
:AmiTree          Open the conversation tree: branch, switch branches, and
                      summarize. Keys: <CR> switch, s summarize, r refresh, q.

                                                                 *:AmiModel*
:AmiModel [slot]
                      Pick a model for a registered slot (live list from the
                      slot's provider). No argument prompts for which slot. Slots:
                      default, chat, and any an extension registers (e.g. fim).

                                                                *:AmiModels*
:AmiModels        Show each model slot's current model.

                                                            *:AmiExtensions*
:AmiExtensions    List the loaded extensions. Extensions add their own commands
                  (e.g. ami-inline.nvim adds :AmiComplete / :AmiInlineAuto;
                  ami-custom-proactive.nvim adds :AmiProactive / :AmiNudge). See
                  |ami-extensions|.

                                                                *:AmiDaemon*
:AmiDaemon [start|stop|restart]
                      Control the managed daemon (default restart).

                                                                *:AmiHealth*
:AmiHealth        Ping the daemon and report its status.

                                                                   *:AmiLog*
:AmiLog           Open the log viewer. *:AmiDebug* toggles verbose logs.

6. CONFIGURATION                                         *ami-configuration*

Defaults (pass overrides to |ami.setup()|): >
    require("ami").setup({
      daemon_url = "http://127.0.0.1:8787",
      model = {                     -- default model slot (every slot falls back here)
        endpoint = "http://localhost:1234/v1",
        model = "qwen3-coder",      -- pick per slot live with :AmiModel
      },
      chat = {                      -- chat/advisor provider (via the daemon)
        -- endpoint, model          -- omit to inherit the default `model` slot
        ui = {                      -- chat panel placement/appearance
          position = "right",       -- "right" | "left" | "center"
          width = 0.4, height = 0.9,-- fraction of screen (<=1) or absolute cells
          opacity = 0.8,            -- 0..1; lower = more see-through ('winblend')
          margin = 2,               -- gap in columns from the screen edge
        },
      },
      session_dir = nil,            -- nil = stdpath("data")/ami
                                    --  ""  = each project's ./.ami/sessions
      daemon = {
        auto_start = true, auto_build = true, bin = nil,
      },
      context = {
        lsp_deps = true, dep_max_files = 5,
        dep_timeout_ms = 1500, dep_max_positions = 30,
      },
      extensions = {},          -- extension specs or module names to register
      disable_extensions = {},  -- names of extensions to skip
    })
<
Inline completion is the ami-inline.nvim extension; install it and add
require("ami-inline") to `extensions`. An extension's own options live under its
name (e.g. `inline = { ... }`, `proactive = { ... }`). See |ami-extensions|.
==============================================================================
7. EXTENSIONS                                             *ami-extensions*

ami keeps a small core; optional features are extensions — self-contained Lua
specs that hook the lifecycle through a stable API instead of core internals.
Register specs, or module names to require(), in |ami.setup()|: >
    require("ami").setup({
      extensions = {
        require("ami-custom-proactive"),  -- a spec table
        "my-org.ami-notes",               -- or a module name to require()
      },
      -- disable_extensions = { "proactive" },
    })
<
ami ships no active extensions itself. Proactive suggestions (formerly built in)
now live in the ami-custom-proactive.nvim repo. `:AmiExtensions` lists what is
loaded. Lifecycle events: setup, context_assembled, chat_turn_pre,
chat_turn_post, buf_write.

Full API, event reference, and a guide to writing/publishing your own are in
docs/extensions.md in the repository.

==============================================================================
8. HOW IT WORKS                                           *ami-architecture*

  Neovim (Lua)  --HTTP+SSE-->  amid (Go)  --OpenAI API-->  LM Studio

The daemon is reference-counted across Neovim instances: it is shared while any
instance is attached and stopped only when the last one exits. Inline completion
talks to LM Studio directly (not through the daemon) to keep latency low.

Conversation history is a branching tree stored under `session_dir`
(default stdpath("data")/ami/<project>/), kept out of your repositories.

==============================================================================
9. HEALTH                                                       *ami-health*

Run `:checkhealth ami` to verify Neovim version, curl, Go, the daemon
binary, the daemon, and LM Studio reachability.
